# AI 约定主动唤醒

本功能分支增加一次性主动唤醒约定，尚未合并或公开发布。与按随机间隔检查的主动消息共用后台生成、当前会话配置、工具链、通知和免打扰规则，无需新服务器。

## 怎么使用

1. 设置 → 主动消息，打开总开关，再打开默认关闭的“允许 AI 约定主动唤醒”。
2. 在聊天中说“今晚九点半来找我”。AI 可以调用 `proactive_wakeup` 保存具体日期、分钟和约定背景，也可以根据对话自行决定下次来找用户的时间。需要当前模型支持工具调用。
3. 约定绑定调用工具的角色和会话；每个会话保留一个待执行约定。新约定只替换同角色、同会话的待执行项，不覆盖其他会话，也不取消正在执行的当前约定。
4. 可在主动消息设置中查看、取消；也可以让 AI 查看或取消当前会话的约定。关闭总开关或此功能会取消未完成约定，再开启不会复活这些已取消项。

有待执行约定时优先等待最近的约定时间，不做随机提前检查；所有约定执行完后恢复原来的间隔检查。手动“立即测试一次”保持原行为，不消耗预约。

## 到点会发生什么

- 到点重新读取约定角色的原会话，沿用该会话当前的模型、上下文摘要、人设和工具，发起真实主动生成。约定背景只作为背景资料，不是预先写死的通知文案。
- 即使之前触发过连续追问上限或用户刚发过消息，明确的到点约定仍可执行；原会话正在生成时延后一小段时间，不抢占正常聊天。用户在生成期间回来时清理本次未完成结果，稍后再试。
- 免打扰时段内顺延到允许时段；执行途中关闭功能、取消任务、拉黑会话等仍会拦截后续模型/工具步骤和发送。
- AI 仍可能选择不发正文；失败、空回或选择等待时，界面记录为未完成，用户可以让 AI 重新安排。不会因模型失败自动无限重试。
- AlarmManager 与 WorkManager 共用持久化任务身份和原子认领，避免同一预约被两个触发源同时执行。任务写入 DataStore，进程重启仍保留未到期预约；上个进程留下的执行中任务标记中断，不静默重发可能已执行过的模型/工具操作。

日期按创建预约时手机的本地时区解释，保存为具体时间点；更改手机时区后不重写原来的时间点。精确闹钟、后台运行、网络和系统省电影响实际触发时间，无法承诺设备强制停止或断网时仍准点送达。沿用主动消息页已有的后台与精确闹钟设置。

工具只有在总开关和新开关都开启、当前会话可交互时注册，后台工作流不注册此入口。启用按需工具后它归入常驻的“时间与提醒”；未启用本功能时不会额外发送这份工具说明。保存预约不额外发起模型判定；到点生成按既有主动消息流程调用用户配置的模型。

## 验证

JVM 回归覆盖本地时间解析、非法/过去时间、夏令时空缺和重复时段、跨午夜免打扰、两个开关、未来时间不提前认领、原子去重、角色/会话隔离、取消后旧结果不得覆盖、忙时顺延、结果状态、历史保留、旧设置兼容和 JSON 往返、进程中断恢复、预约优先与恢复随机检查。Compose 设备回归覆盖开关和取消入口。

实际模型能否自然决定预约、锁屏后台到点触发、网络中断和通知送达仍需测试包真机确认。当前版本号未变，不会推送线上更新；构建结果以 Actions 为准。
