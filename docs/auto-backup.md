# 本地自动备份

入口：设置 → 备份 → 导入／导出 → 自动备份。默认关闭；先用系统文件夹选择器授权，再启用。

- 间隔：每天、每 3／7／15 天。默认手机本地时间 03:00，可修改。
- 开启后的首次任务安排在下一次所选时间；周期按上次成功备份的本地日期计算。立即备份成功也会重置到期日期。
- 使用 WorkManager 唯一周期任务，重启后仍可调度；启动应用时恢复调度，修改配置重排，关闭取消周期任务。每日检查是否到期，不需要 AI、网络或精确闹钟权限。
- 系统省电、强制停止和后台配额会延迟执行，不能保证严格 03:00。运行时使用 dataSync 前台通知；周期失败最多两次退避重试，页面显示错误，失败不更新成功日期。
- “立即备份”同样后台执行，可以关闭设置页等待完成；它不要求开启自动备份。

## 格式与隔离

复用现有本地 ZIP 导出／导入，包含设置、数据库、上传附件、skills、插件文件和插件设置。不改变数据库 schema。正式签名 APK 与记忆 debug 保持独立。

自动备份计划、成功状态、文件句柄放在单独的设备本地 DataStore，故意不装入导出包，避免在另一台设备导入后误开启任务或复用失效授权。

数据库在 Room 写事务下复制匹配的主库/WAL 快照，再释放事务打包；不复制可重建的 SHM 文件。手动导出也复用此快照过程。快照创建与本地／WebDAV／S3 恢复用同一个进程内锁互斥，避免直接恢复文件时发生自动快照。文件和设置不是跨资源全局事务；备份期间避免主动导入、删除大量附件或修改插件。

## 一份最新与失败保护

1. 使用独立临时文件准备 ZIP；插件设置导出失败视为整次失败。
2. 逐项检查 ZIP 大小与 CRC，必须有 settings.json 与数据库。
3. 在所选文件夹创建候选文件，先持久保存恢复指针，再流式写入并完整读回 SHA-256 校验。
4. 校验成功后原子记录新文件与成功时间，把前一份由本功能管理的 URI 记入清理列表。
5. 最后删除旧文件；只操作本功能记录的文件，不遍历删除用户的手动备份或其他文件。

正常结束在当前目录只留一份最新 ZIP，替换期间短暂存在两份。更换目录后保留旧目录已有文件，只管理新目录，避免失效的旧授权阻断新备份。写入、校验、取消、权限或空间问题不会先删除旧备份。取消后清理候选文件；进程中断留下的候选／旧文件通过恢复记录在下次执行时清理。旧文件删除失败会提示，下次先重试清理，未清完不继续创建新版本，避免无限堆积。

Android 文档提供器的“创建文件”和本地 DataStore 不能组成一个跨进程事务；如果进程恰在创建完成、记录 URI 前被强杀，可能留下一个空候选文件。不会为清理它而扫描删除用户目录；可手动删除空文件。导入到其他设备后需要重新选择备份目录。

## 验证

新增 12 个 JVM 用例，覆盖初始时间、日历间隔、夏令时、参数校验、完整 ZIP、CRC 损坏、读回不一致、写入失败、取消、发布顺序记录及中途修改设置。独立 Kotlin 编译运行通过；实际 SQLite WAL 文件快照检查通过，包括并发写锁、完整性、原历史保留和排除后续写入。

完整 Android 编译、JVM 和 Release lint 交由 CI。SAF 文件夹授权、前台通知、系统后台调度与从生成的 ZIP 真正导入，仍需真机验证。
