# 工具按需加载（Debug 试验）

普通聊天和主动消息可以按角色选择按需发送工具定义：常用工具保持完整说明，其余已启用工具保留名称和一句用途的目录。AI 用 `tool_discovery` 搜索或加载，下一次模型请求收到目标工具的原始定义，然后正常执行。

旧配置默认关闭，关闭立即恢复后续轮次的全量模式。Release 不启用此试验。不修改后台工作流的完整工具注册表、既有权限、审批规则、角色隔离或音乐歌词感想的独立请求。

## 常驻范围

- 内置记忆、拍一拍、贴表情/颜表情、一起听。
- 联网搜索和网页读取；查时间、闹钟、倒计时、系统日历；朗读、选项提问、剪贴板。
- 已启用插件中的表情包列表/发送、当前天气/简要天气/预报。
- OB 外置记忆库整组：默认按 read_memory、recall_memory、propose_memory 接口签名识别，不依赖服务昵称；可以在角色的 MCP 页面手动调整整组常驻。

常驻只决定模型看见多少说明，不会启用原本关闭的功能。其余工具包括主动电话、工作流、SSH、文件、图表、游戏等，仍可通过目录发现和加载。

## 生命周期与边界

- 目录排序固定、每条用途最多 88 字符，每次请求均可见；目录属于 provider 副本，不写入历史或记忆。
- 搜索仅在本地匹配已有名称/说明，最多返回 8 项；加载使用完整来源名称，每次最多 8 个，校验整批名称成功后才生效。搜索和加载都不执行目标工具。
- 加载集合只在本轮工具链有效；后续每步继续暴露已加载定义，下一次用户/主动消息轮次重置。暂停审批后可恢复仍可用的原定义。
- MCP 和插件保留现有命名空间；同名工具不能用裸名互换。加载不会绕过审批，也不能在同一批中直接执行原先尚未暴露的目标工具。
- 若用户自定义请求体覆盖 tools/tool_choice/functions/function_call/messages/system/contents/input，保留自定义设置、回退全量模式。
- 首次加载会增加模型往返；搜索与加载也计入既有工具步数限制。没有额外模型来做路由，不自动重试具有副作用的目标工具。
- 协议单测不能证明所有模型会主动查找。真实模型的自然查找、额外延迟和实际输入量必须真机验收。

## 设置与验收

1. 角色设置 → 本地工具 → 打开「工具按需加载（实验）」；角色 MCP 页面核对 OB 的「这组工具完整常驻」。
2. 试普通聊天、表情包、拍一拍、天气、一起听，确认常驻工具无需先加载。
3. 不提工具名，分别说「陪我玩大富翁」「帮我看看服务器日志」「我想看看漂流瓶」，观察是否自行查找、加载并调用正确来源的工具。
4. 对比回复下方「请求体积」的全量定义、实际定义和目录。这是 UTF-8 字节，不是计费 token；工具链累计输入不等于单次上下文。
5. 试加载后工具的审批暂停/恢复，确认审批和执行各发生一次；关闭试验后检查恢复全量。

新增 17 项测试覆盖查找/加载、连续调用、同批不可越权执行、审批恢复、来源重名、不可用工具、OB 与插件常驻策略、旧配置回退、自定义参数、provider 副本和目录计入体积。体积测试使用可复现的合成 141 工具清单，不冒充用户私有 MCP 的测量结果。
