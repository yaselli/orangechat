# 西瓜瓣记忆改造：已确认方案与实现进度

本文件记录本次约定，替代参考项目里的自动 compact 规则。日常正式版使用 release；记忆开发使用现有 debug，不新增包名。开发分支 `feature/memory-system`，暂不合并正式分支。

## 1. 数据分层

- 人设、系统提示词、助手配置：始终直接读取当前配置，不变成长期记忆。
- 原始历史：本地 Room / SQLite 中保留消息节点、分支、工具结果和附件引用，是事实源。
- 会话摘要：单独保存，附带所覆盖消息的身份与内容指纹，仅用于组装请求。
- 长期记忆：偏好、事实、事件、约定等；按助手或全局范围隔离，保留实际来源与版本。
- 知识图谱：实体、关系、对应记忆及证据；与长期记忆关联，不把模型猜测变成永久事实。
- 检索索引：可重建的派生数据，不替代原文；嵌入模型或内容版本变化后失效。

数据存本地，不要求用户部署外部 SQL / 向量数据库。使用远程嵌入时，需由用户配置服务。

## 2. 手动 compact

只手动触发，不做 75% 自动压缩，也不在发送前暗中同步压缩。继续使用独立压缩提示词和压缩模型设置。

流程：验证范围 → 有效旧摘要 + 尚未总结的新对话 → 一份新摘要 → 验证源消息未变化 → 只更新摘要字段。

- 完整历史始终留在同一个窗口；不删除原文、不造一条用户消息来冒充摘要。
- 保留近期条数指“直接发送多少原文”，不是“只保存多少历史”。边界回退到完整轮次，避免切断工具链。
- 摘要默认目标 1500 token；生成目标不是硬性计量保证，受模型和 tokenizer 影响。
- 手动压缩将已有摘要（如有）与本次新增待压缩对话一次交给所选压缩模型，生成一份新摘要；不自动分块或逐块总结。
- 软件不设额外的原文字符数限制，不截断原文；每次手动压缩仅发起一次总结调用。模型容量或接口限制导致失败时保留原文和原有摘要，不自动拆分、重试或增加付费调用。摘要目标输出长度仍由用户选择。
- 输出 token 上限为目标 + 512；模型返回空内容、失败或取消，不推进覆盖范围。
- 压缩期间追加的新消息保留；编辑/删除/重排已覆盖消息、切分支或另一个摘要先完成时，旧结果不得覆盖新状态。
- 覆盖范围只存条数与一个定长指纹，避免长会话把摘要元数据撑成超大数据库行；摘要字段损坏也回退原历史。
- 已有摘要失效时，下一次请求回退到完整历史；重新手动压缩从原文重建，不能继续使用过期摘要。
- 正常聊天、主动消息共用有效性判断；摘要是请求背景，不作为新用户指令，也不持久化成聊天气泡。

## 3. 长期记忆写入与旧数据

保留现有记忆编号、正文、归属；旧记录标为 legacy，未知来源和时间留空，不伪造用户原话。

新建或修改记录保存来源类型、触发写入的真实会话/消息 id、创建/修改时间、递增版本。这个触发消息仅用于追踪写入，不冒充记忆事实的原话证据；精确证据引用在后续整理/索引阶段补齐。工具修改/删除必须验证助手或全局范围，过期修改不能覆盖新版本，已删除记忆不能被旧操作复活。

明确记忆工具仍可保存；后台自动整理默认关闭，开启前必须单独选择辅助模型，不悄悄沿用昂贵聊天模型。每批最多 2 次整理调用，不自动重试相同批次。整理失败不能阻止用户继续聊天。

compact 与长期记忆是独立机制：第一批 compact 不新增后台记忆提取调用；后续整理接入也不能影响原文保留与取消回滚。

## 4. 向量与关键词召回

向量取 20，关键词取 20；先做权限/范围/有效性过滤，再去重融合。无重排模型，采用等权 RRF：每条路线贡献 `1 / (60 + rank)`，rank 从 1 开始；并列顺序使用稳定 id。

索引片段目标 800 token，重叠 100 token，优先沿完整消息/句子边界切。命中后再提取约 400–600 token 的相关原文，不能直接拿 6 × 800 塞进请求。向量命中没有关键词位置时，用句子级匹配或子片段定位，不能假定存在字符偏移。

最终最多 6 个片段，注入总预算 3000 token，包含标题、来源标记、少量常驻记忆（最多 500 token）和图谱结果。超过剩余预算时继续缩短或跳过。会话摘要单列预算，但仍受模型总上下文限制。

检索最多等待 8 秒；超时当轮使用本地关键词等可用结果，不追加第二条聊天回复、不自动重试产生额外远程嵌入费用。

## 5. 缓存与费用

用户关心的是模型供应商的 prompt cache，不只是本地检索缓存。

- 固定人设、工具 schema、固定规则与历史前缀尽量保持一致。
- 动态召回靠近当前轮次放置，不插到整个历史前面反复改变长前缀。
- 格式、顺序稳定，不为每次召回增加随机 id 或时间戳。
- 一轮工具循环复用本轮检索；缓存受内容版本、模型版本与助手范围约束。
- 验证使用前后的 cached input / input 比例及实际费用，不能保证固定命中百分比，更不能未经验证就全量启用。
- 本地缓存要有大小和失效上限；具体索引/缓存实现时补齐可执行参数。

## 6. 知识图谱

纳入本次完整目标，暂不引入重排模型。首期只用一跳关系扩展，最多 4 条，计入同一注入预算。关系要带时间、状态和来源；用户纠正、删记忆时同步失效，不从“喜欢炸鸡因为脆”扩展出没有证据的人生偏好。

## 7. 界面与验证

不在每轮聊天里堆记忆诊断面板；管理页允许纠正、删除、少量常驻。诊断留可选入口。开发可分提交，手机测试按完整批次给包，避免一天反复安装。

记忆测试数据库升级到 v30 / v31 / v33 后，不导回正式版；正式版日常数据保留在独立应用中。

第一批关键检查：旧数据迁移、完整历史/分支/附件保留、连续两次 compact、取消/失败不推进范围、编辑或换分支不套旧摘要、追加消息不被晚到的结果覆盖。

## 8. 当前实现进度

已实现于本批代码：

- Room 29 → 30 增量迁移，旧记忆原样保留并标 legacy。
- 新记忆来源与版本记录，作用域和并发修改校验。
- 独立会话摘要、手动压缩、边界校验、原文保留、摘要失效回退、正常/主动请求接入。
- 手动压缩一次请求，不额外限制原文长度，不自动分块；取消与失败保护、弹窗文案调整。

第二批新增：

- 默认关闭的按需召回开关、独立嵌入模型选择；不修改已有助手开关和旧记忆。
- 长期记忆分片、本地中英文关键词召回、向量召回、等权 RRF、重叠去重与完整注入预算。
- Room 30 → 31 只新增派生向量和轮次快照表；v30 schema 来自上一批 CI 实际 KSP 输出。
- 手动、增量建立向量索引；发送前显示片段数和调用上限。每批 32 个片段，一次操作最多 2048 个 / 64 次调用，确认后新增数据不得放大已批准上限。失败/取消保留完成批次，不自动重试。
- 查询嵌入最多一次，8 秒退化关键词；没有有效向量索引时不调用远程接口。索引或快照异常不阻塞聊天，也不回退整库注入。
- 本地查询向量缓存最多 64 条 / 2 MiB / 10 分钟，模型及服务配置和范围参与键；不缓存可能过期的最终召回结果。
- 当前轮的召回快照持久化，用于重试复用；同一工具循环复用并逐步重验源记录。模型请求副本追加背景，不写入原消息，不把旧轮召回累积到历史。
- 正常聊天、主动消息使用相同召回服务与作用域；关闭后继续旧机制。
- 记忆工具支持读取完整记录，避免把召回片段当完整记忆直接覆盖。内部固定编号继续保留，不因删除重新编号。

第二批实现边界：

- 索引/召回目前覆盖 `MemoryEntity` 的长期记忆，尚未索引原始历史。
- 向量通过已有 OpenAI 兼容 `/embeddings` 实现；原生 Google/Claude 的嵌入接口尚未实现。关键词无需远程配置。
- 尚无模型专属 tokenizer，首期使用 UTF-8 字节数作为保守预算：片段 800、重叠 100、命中窗口最多 600、完整背景块最多 3000 字节。中文会比目标 token 数更短，不能把此计量宣称为所有厂商的精确 token 数。标签/分隔符同样计入。
- 用户纠正/删除造成旧源无效时即停止引用，不在每次重试自动重新付费。下一轮重新召回，新增/修改记忆在手动更新向量索引前仍可由关键词命中。
- 快照最多保留 1024 条（每条至多 6 个片段、正文受 3000 预算限制），按最旧时间淘汰；删除会话级联删快照、删除记忆级联删向量。派生数据不参与恢复原文。
- 所有召回只放到当前 USER 的请求副本末尾，附明确背景边界，不新增伪造用户轮次，不放进 Google 会收集到最前面的动态 SYSTEM。历史前缀保持原文；上一轮临时背景移除仍可能影响末段缓存，因此必须实测，不能保证原有命中百分比。
- 启用前后真实接口的 cached input / input 和账单 A/B 对比尚未完成；默认关闭，不能宣称已达到 80–92%。

尚未实现，不能当作已经上线：常驻记忆管理、图谱存储与扩展、后台整理、真实费用/缓存对比。原始历史检索由下面第三批接入。

默认仍沿用旧的长期记忆注入方式；用户主动打开测试开关后才启用第二批召回。继续在同一个 debug 分支完成后续目标，手机验证仍合成完整批次。


第二批验证记录：新增 24 个 JVM 回归用例、1 个 v30 → v31 设备迁移用例。已在本地独立 Kotlin 编译器与断言运行器下运行其中 13 个实际核心算法用例（分片/预算/RRF/向量校验/有界缓存）并通过；两段实际迁移 SQL 在 SQLite 检查通过。完整 Android 编译、标准 Gradle 全套 JVM 测试和 Lint 交由 CI；设备迁移用例尚需模拟器/设备运行。上述检查不等于已经完成真实供应商缓存率或手机体验验证。


## 9. 第三批：原始历史检索

- 新增独立的“同时检索当前助手的聊天历史”开关，默认关闭，依赖按需召回测试开关。无论是否使用全局长期记忆，原始历史都只属于当前助手，不跨助手共享。
- 从本地 message_node 当前 select_index 指向的普通 USER/ASSISTANT 文字提取来源。SQL 只返回文字、角色、日期与身份，不反序列化图片/base64；思考、工具、附件和有类型的额外背景排除。当前版本跳过普通文字超过 64000 字符的单条消息，不伪称全文已索引。
- 关键词复用本地 FTS，限定助手、选中分支、当前轮之前和时间边界后再取至多 80 个候选，再与长期记忆一起排名取关键词前 20。旧 FTS 曾只保留前 10000 字符，新增“更新历史关键词索引（本地）”修复当前助手的合格旧记录，无 API 调用；新消息普通文字索引上限改为 64000。
- 原始历史也可手动、增量建立向量。每次确认最多 2048 个片段／64 次调用，超过时分为下一次手动操作，不自动续费。未选嵌入模型仍可用关键词；索引确认文案明确会把当前助手的历史普通文字发送给用户选定的嵌入服务。
- 长期记忆和历史共用一次查询嵌入、20 个关键词与 20 个向量候选、等权 RRF、至多 6 片段和完整 3000 UTF-8 字节预算。来源标签与角色／日期计入预算，AI 说的话不会标成用户原话。
- 历史向量分页读取，每页 64 条，保留至多 80 个轻量候选，最终仍从实时来源验证后取前 20；不把整库向量一次读入内存。查询和向量搜索仍受原有 8 秒限制；失败退化本地关键词，不加第二次付费查询。
- 同会话已直接发送给模型的历史不重复召回；重新生成早期消息时排除后续节点，其他窗口也排除当前轮时间之后的消息。合格原文按来源身份与指纹验证；切分支、修改、删除、改助手后旧引用失效。
- 每轮快照保存具体来源，不保存一个永久有效的“最终检索结果缓存”。工具循环和重试继续复用本轮结果，每次使用时重新验证当前选中原文；不反复搜索／付费，也不把临时背景写进聊天气泡或前置 SYSTEM。查询剔除额外时间背景，固定人设／工具 schema 不改。
- Room v31 → v33 只新增 history_memory_vector，外键指向原消息节点；现有节点更新采用 REPLACE，旧索引随改动／删除级联清理。回包写索引时在同一数据库事务内再次校验，不能复活已删除或旧分支。原始记录、旧向量和轮次快照保留。
- 跳过 v32 是为了不与独立稳定版的互动 v32 混用。当前只支持记忆 debug 的 v31 → v33，不提供正式版 v32 → 本实验 schema 的直接迁移；最终合入需新的统一迁移。正式版的拍一拍／表情／自动备份代码未带入本分支。

第三批验证：新增 13 个 JVM 回归（6 个纯算法、4 个服务调用／失效、3 个快照／背景隔离）和 1 个 v31 → v33 设备迁移用例。6 个新算法和 9 个已有检索算法已独立 Kotlin 编译执行通过；真实 SQLite 执行生产迁移、选中文本与向量 SQL、FTS 绑定查询，验证原数据保留、范围／分支／时间过滤与级联清理。完整 Android 编译、标准 JVM、设备测试源码编译和 Lint 由 CI 执行；设备迁移、原生中文 FTS 及真实供应商缓存／费用仍需实测。
