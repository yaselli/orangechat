# 第三阶段：统一消息追加与按 ID 更新

基线：`84596ce`（glass），上一批多轮工具循环已合并并通过真机验收。

普通流式聊天和主动消息共用 `Conversation.updateGenerationMessages()`：

- 已有消息按 UIMessage.id 定位并更新，保留 MessageNode.id、其他备选消息和选中状态。
- 新消息追加新节点，不按请求历史中的旧位置塞进其他消息的节点。
- 普通重新生成只允许指定的新回复进入原目标节点，作为选中的新备选版本。
  目标以节点 ID 固定，后续流式帧继续更新同一个回复 ID。
- 当前对话里新增的其他节点、收藏、标题、建议、文件夹等信息保持原样。
- 本轮开始时已有的消息，以及本轮已处理过的回复，如果后来被删除，后续流式帧不再追加。
  普通聊天保留本轮见过的 ID；主动消息复用已有的本轮归属 ID。重新生成目标节点被删时
  忽略该目标的新回复，不改成追加到末尾。

主动消息仍先执行原消息归属校验，再在原会话锁内更新并保存。
普通流式 chunk 的读取和发布也在现有 saveMutex 内完成，锁不包住模型请求。
应用拉黑自动回执继续使用原独立路径，不经过普通更新函数。
预设消息初始化的 `updateCurrentMessages()` 不改；取消、错误清理、最终保存等留待后续批次。

共 16 项纯逻辑回归测试，覆盖流式更新、节点移位、并发追加消息的状态快照、
备选版本/选中状态、重新生成目标、缺失目标、思考与工具、元数据和主动消息归属保护，
以及生成中删除历史、删除本轮回复、删除备选、删除重新生成节点后旧帧不复活消息。
这些测试验证消息合并逻辑，不代表整套并发保存和取消已完成统一。

本地缺少 Gradle 9.4.1 且下载网络不可达；独立分支工作流执行测试、Lint 与 APK。
工作流自行运行，待 CI 和真机反馈后合并。

真机重点：普通文字/图片流式回复、重新生成与备选切换、多轮工具、主动消息、
退出重进后历史完整；停止和失败处理仍应与上一版一致。
