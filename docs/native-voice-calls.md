# 原声输入通话

本功能在现有语音通话中增加可选的原声输入。用户明确取消了 Gemini Live：不建立 Live WebSocket、不更换聊天模型或 TTS、不增加独立实时语音接口。

## 使用

1. 给当前会话选择支持音频输入的模型（例如 Gemini），按原来的方式配置 TTS。
2. 设置 → 语音 → 输入与通话，开启「通话时发送原声」，然后发起通话。默认关闭；模式在通话启动时确定，切换后下次通话生效。
3. 说完后停顿约 0.9 秒，应用将这段 WAV 录音直接发送。通话页显示「原声输入 · TTS 回复」，原声模式没有识别字幕，录音作为可回放音频消息保存在当前会话。
4. 回复继续使用原有 TTS。开启「AI 回复时继续监听」时可以再次说话打断；关闭时回复期间停止采集，可点「打断，继续说」恢复麦克风。静音和挂断均停止采集，静音不会触发发送残留录音。

关闭原声输入后仍使用原来的 ASR 转文字通话。普通聊天、角色提示词、记忆、工具、审批和发送队列继续共用原有生成流程。原声模式不创建 ASR 实例、不调用识别服务、不将语音先变成文字。

传输兼容沿用现有录音附件：Google / Gemini 原生接口（含 Interactions）和支持 input_audio 的 OpenAI Chat Completions 兼容接口。仅接口类型可预检，具体模型和中转服务仍必须支持音频；不支持时显示错误，不静默转写或自动重试。

## 实现与边界

- 本地 AudioRecord 录制 16 kHz、单声道、PCM16，20 ms 一帧；能量检测维持 200 ms 前缓冲，900 ms 静音分句，过滤过短声音。每段最多 30 秒、960 kB PCM，发送时加真实 WAV 头。
- VOICE_COMMUNICATION 采集源，设备支持时启用回声消除和降噪。能量检测不是人声识别，嘈杂环境或外放可能误触发；建议使用耳机，或关闭回复期间监听。
- 单一协程拥有麦克风，暂停后释放设备。静音与监听设置的变更会使缓存帧失效；取消后释放效果器和 AudioRecord，禁止旧回调继续发送。
- 完成录音先保存为现有聊天附件，入队后由会话持有；发送失败、挂断或取消时清理尚未移交的附件与临时文件，不删除已在聊天中的录音。
- 打断和挂断按用户消息 ID 处理，只撤销本通话持有的排队/生成回复。取消中的待执行工具在该生成任务释放队列前完成取消回执，不执行或重试目标工具，不改写后续用户回合和未选中的分支。
- 原声输入默认关闭；「AI 回复时继续监听」默认开启。两个开关均持久化，原实现中仅声明而未保存的继续监听开关同时补全读写。

## 检查与真机验收

新增 15 项 JVM 测试：分句及 PCM 保真 8 项，原声消息传输/设置兼容 3 项，回复取消及工具回执隔离 4 项。Android 测试覆盖真实麦克风取消后再次录音、静音时不产生帧。这些测试不使用真实模型、ASR、TTS 或 API 密钥，不能替代端到端通话验收。

本地已执行分句 8 项与既有 WAV 2 项检查；完整 JVM、Android 编译、麦克风设备测试、Lint、APK 打包由 feature/gemini-audio-call 的 Debug CI 执行。提交后让 CI 后台运行，不持续轮询。

真机重点：原声开启且不配置 ASR 时可以发出可回放的录音；Gemini 能回应录音内容、TTS 声音保持原配置；连续交谈、静音后恢复、手动/说话打断、后台及通知栏挂断；挂断后普通聊天正常、重新通话能再次占用麦克风；关闭原声后旧 ASR 通话正常。模型对语气、笑声等声音特征的理解取决于模型本身。

参考接口：[Gemini 音频理解](https://ai.google.dev/gemini-api/docs/audio)。录音发送复用本仓库现有 Google/OpenAI 音频附件编码；没有从参考仓库整体合并语音服务。
