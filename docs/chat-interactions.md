# 头像互动与消息表情

两项独立功能，设置位于助手的基本设置；可以分别关闭。与记忆开发同用现有 debug，不修改正式分支。

## 头像互动

- 双击聊天头像触发。动作和后缀按助手分别配置“你对 AI”和“AI 对你”两组。
- 例如动作“揉了揉”、后缀“的脑袋，并递来一杯牛奶”，组合为“哥哥揉了揉你的脑袋，并递来一杯牛奶”。标点由后缀自己控制。
- 你触发时作为真实的用户互动事件进入现有发送/取消/主动计时生命周期，会产生一次 AI 回复；生成中暂不接收新的双击，避免打断正在进行的回复。
- AI 通过 `avatar_interaction` 工具执行当前配置的动作，追加居中灰字通知，不因此再发起另一轮后台回复。
- 事件使用独立消息节点及带类型的 annotation 保存，显示为灰字；没有“匹配用户输入里某个标记就隐藏气泡”的文本判断。普通文字不被误认为事件。
- AI 创建的 SYSTEM 事件不作为系统指令发送；工具结果有明确 actor / target，用户事件的请求副本同样说明发起者和对象。
- 头像动画只改变绘制，不改布局；原头像 Surface 在聊天中不再截获父级双击，设置页原有头像点击保持原样。恢复历史时不回放旧动画，动画取消时归零。

## 消息表情

- 从消息的“更多”菜单选择“贴表情”；分气泡时可选具体句子。
- 已贴的表情显示在对应气泡下方，按 emoji 合并、计数；点同一个表情切换你自己的反应，旁边加号可继续添加。
- 初始使用 12 个 Unicode emoji，无须远程图片库。不在每条空消息下面常驻一个添加按钮。
- AI 通过独立 `message_reaction` 工具添加或移除自己的反应；支持最后一条用户/AI 消息、唯一原句匹配或精确消息 ID。不能删用户的表情，重复 add/remove 幂等。
- 使用单独 Room 表，键包含会话、消息、发起者、emoji、原句；不修改原消息正文，不因流式保存旧快照丢失。
- 仅能操作当前助手、当前会话和当前分支的消息；编辑生成新分支不会继承旧句子的反应。删除消息清理对应反应，删除会话级联清理；分叉会话复制已有反应并重新生成隔离键。
- 贴表情本身不触发模型调用。下一次请求附带至多 24 条有效反应，每句引用最多 80 字，作为末尾的应用背景；未发生反应时不增加这段提示。手动 compact 后仍能引用本轮允许范围内的原消息，重新生成不会看到目标之后的反应。
- 表情按原始气泡文本关联。切换显示分气泡规则或视觉正则后，展示可能变化；不对历史原文做改写。

## 迁移与验证

- Room v31 → v32 只新增 `message_reaction`，保留消息、分支、记忆、压缩摘要和向量索引。
- v31 schema 来自上一批成功 CI 的 KSP 输出。新增设备迁移用例检查 v32 的实际 Room schema。
- 本地实际 SQLite 检查覆盖原文保留、幂等、双方隔离、分叉隔离、消息/会话删除；3 个独立编译运行的格式/键回归通过。
- 共新增 8 个 JVM 用例，覆盖事件序列化、类型识别、分气泡/代码块、目标解析与隐藏分支；完整 Android 编译、标准 JVM 测试和 Lint 交由 CI。设备迁移测试与触屏手势/布局还需设备验证。
