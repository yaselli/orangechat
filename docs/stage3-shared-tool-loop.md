# 第三阶段：共用多轮工具循环

基线：`510d5bb`，`feature/liquid-glass-ui`；上一批单轮模型调用已合并且通过真机验证。

普通聊天和主动消息现在共用 `runGenerationToolLoop()`，统一逐轮生成、待执行工具选择、
顺序执行、按 toolCallId 写回结果、带结果继续生成，以及循环结束。取消和失败不在循环内
吞掉，也不自动重试，仍交给入口的现有清理逻辑。

## 入口保留的规则

| 普通聊天 | 主动消息 |
|---|---|
| 支持已有批准/拒绝/回答的工具直接恢复，不先重新请求模型 | 不恢复历史工具，先建立本轮新 assistant 消息 |
| 按原有自动批准、全局确认、工具确认规则暂停 | 使用入口已筛选的后台工具权限；查岗许可不变 |
| 维持 maxSteps 的原有迭代计数，包括恢复步骤 | 12 轮工具之后保留一次模型回答；再要求工具则报错并由入口清理 |
| 工具结果更新沿用原输出转换和 Flow 展示 | 工具结果更新继续经新消息 ID 校验与会话锁保存 |

公共循环通过回调使用已有单轮模型调用、工具执行与入口保存代码，不修改提示词、调度、
PASS/WAIT/STOP/JUMP、thinking 无正文收尾、工具清单、模型参数或 UI。
`generateWithTools()` 现在仅适配主动消息的流式展示、输出转换、思考收尾和诊断日志；
自身不再维护另一套工具循环。

## 验证

新增 `GenerationToolLoopTest` 的 15 项回归测试：多轮结果传回、批量审批暂停、
批准/拒绝/回答恢复、Pending 保护、确认规则优先级、最终回答预算、超限报错、
普通迭代限制、零步骤、主动控制标记、失败/缺失工具、已完成工具去重、工具取消、
模型失败、保存失败。

本地缺少 Gradle 9.4.1，下载网络不可达；测试、Lint 和 APK 由独立分支原工作流执行。
提交后等待 CI 和真机结果，再合并到 glass，不持续轮询。

重新进入对话检查历史、思考和工具展示完整。
