# 西瓜瓣 · 一起听歌服务

这是供西瓜瓣 Android 客户端连接的自部署音乐服务。每个人在自己的服务器上运行一份，连接自己的服务、分别登录自己的网易云或 QQ 音乐，不需要我们提供公共服务器。网易云部分复用 [one-earbud](https://github.com/isle0306ral-hub/one-earbud) 的网易云协议、歌词、队列和 AI 工具实现。来源提交和 MIT 许可证保留在 `vendor/one-earbud/`；QQ 音乐协议使用固定版本的 [QQMusicApi 0.7.3](https://github.com/L-1124/QQMusicApi/tree/v0.7.3)，来源与 GPL 许可证保留在 `vendor/qqmusic-api-python/`。客户端适配与设备隔离代码位于 `src/`，本服务与西瓜瓣采用 AGPLv3。

## 用户体验

1. 在自己的服务器部署下方的配套服务。在西瓜瓣的设置或聊天「＋ → 一起听歌」中，填写自己的 HTTPS 服务地址和部署时设置的访问口令。
2. 选择「网易云音乐」或「QQ 音乐」。网易云用网易云 APP 扫码，QQ 音乐用手机 QQ 扫码授权；同一台手机可先保存二维码，再从扫一扫的相册入口选择。本批 QQ 音乐提供 QQ 授权登录，暂不提供微信登录。
3. 搜歌或浏览自己的歌单。网易云有每日推荐、私人雷达；QQ 音乐有猜你喜欢、雷达推荐和我喜欢。支持播放、暂停、拖进度、切歌、顺序/随机/单曲循环、排队、调整顺序和移除歌曲。
4. 打开「和当前角色一起听」，允许该角色读取当前歌曲与附近歌词、搜索、读歌词、分享歌卡和排歌。音频在手机播放器播放，AI 收到的是文字状态。
5. 用户分享的歌曲先进入输入框草稿，可附一句话再发送。AI 分享的歌卡随工具结果保存并独立显示；翻历史记录不自动播放旧卡。

账号、歌单和播放状态保存在各自的服务端。访问口令只用于首次连接；每个安装实例随后获得独立随机凭据，扫码、平台登录态、队列、幂等结果和实时播放状态都按该凭据隔离。即使自己的多个设备连同一台服务器，也不会互相覆盖。换设备或卸载后需要重新扫码，不自动合并两台设备的队列。同一设备的两个平台也分别保存账号、播放队列和实时状态；切换平台会先停止当前音频，旧歌卡保留所属平台，点击播放时明确切回。

## 部署

要求 Docker Compose，或 Node.js 22.9 以上及 Python 3.11 以上。Docker 镜像已经包含 QQ 协议所需的 Python 环境，手机无需安装 Python。手机通过 HTTPS 连接服务；下方示例使用现有反向代理提供证书，不直接公开容器的明文端口。

```bash
cd services/shared-music
cp .env.example .env
# 编辑 .env，设置 ONE_EARBUD_TOKEN 后再启动
docker compose up -d --build
```

如果下载的是 `watermelon-music-service.zip`，先解压并进入包含 `compose.yml` 的目录，不需要上面的 `cd services/shared-music`。在 `.env` 中设置 `ONE_EARBUD_TOKEN`，使用随机生成的 16–256 位英文字母、数字或常见符号（不含空格）。例如可用 `openssl rand -hex 24` 生成，再粘贴到 `ONE_EARBUD_TOKEN=` 后面。此口令由自己保管并填入客户端；不要提交 `.env`。

Compose 默认只把端口映射到本机 `127.0.0.1:8787`。在现有 HTTPS 反向代理中转发到这个地址；例如 Caddy：

```caddy
music.example.com {
    reverse_proxy 127.0.0.1:8787
}
```

将自己配置好的 HTTPS 地址填入客户端的「音乐服务地址」，将 `.env` 中的口令填入「音乐服务访问口令」，连接后选择平台，再生成对应的登录二维码。

不用 Docker 时（先复制并编辑 `.env`）：

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
npm ci --ignore-scripts
QQ_PYTHON="$PWD/.venv/bin/python" npm test
.venv/bin/python -m unittest discover -s test -p test_qq_worker.py
# npm start 会读取 .env
QQ_PYTHON="$PWD/.venv/bin/python" DATA_DIR=/path/to/private/music-data PORT=8787 npm start
```

`DATA_DIR` 必须是服务专用目录。`MAX_USERS` 默认为 32 个安装凭据；首次配对需要正确的访问口令，每 IP 每小时限 6 次，音乐请求每 IP 每分钟限 600 次。`MAX_ACTIVE_USERS` 默认同时缓存 8 个活跃安装；资源足够时可自行提高。最近三分钟内活跃的账号不会因缓存挤压丢失待扫二维码，达到容量时返回繁忙。每个凭据同时最多排队 20 个操作，避免重复操作无限积压。反向代理只有在服务端口无法绕过代理访问时才启用 `TRUST_PROXY=1`；Compose 已绑定本机端口。直接用 Node 运行时，也应通过防火墙限制该端口仅供反向代理访问。

## 账号与状态

- 随机凭据只返回给创建它的客户端一次；服务器使用其 SHA-256 作为目录名，不保存凭据原文。请求不接受客户端传入的用户 ID 或数据路径。
- 网易云登录态保存在设备目录内的 `netease-auth.json`，QQ 音乐凭据保存在同一设备的 `qq/auth.json`，文件权限 `0600`、用户目录 `0700`。登录态不会通过接口返回给客户端或模型；服务管理员仍需保护整个数据卷及其备份。
- Android 用 Keystore 加密自己的连接凭据，保存在不参与备份的目录中。客户端不保存网易云 Cookie 或 QQ 音乐登录凭据，不向模型提供服务凭据。
- 实时播放状态只在服务内存中，心跳过期后移除；客户端仅在播放/近期暂停时为已开启的角色提供一小段实时背景。不会每秒调用模型，也不把自动音乐背景写进聊天历史或记忆。
- 「退出登录」只清除当前平台的登录态、待扫二维码、队列和实时状态，另一平台不受影响。「断开此音乐服务」撤销设备凭据并删除两个平台的登录数据。服务离线时可以清除本机连接，但客户端会明确提示无法确认清除远端登录。
- 使用平台非官方接口，歌曲可播范围取决于账号权限、版权和接口可用性；没有绕过会员或版权限制。

## 验证与当前范围

```bash
QQ_PYTHON="$PWD/.venv/bin/python" npm test
.venv/bin/python -m unittest discover -s test -p test_qq_worker.py
```

包含 44 项 Node 测试：上游 26 项、原设备隔离与私有服务配对 9 项、QQ 平台适配、登录门禁、搜索缓存与实际 Python 工作进程边界 9 项；另有 6 项 Python 映射、歌词、地址和凭据兼容测试，不访问真实账号。另有 19 项 Android JVM 测试，覆盖状态过期、角色隔离、请求副本、歌曲草稿、平台兼容、试听标记、访问口令配对和 HTTPS/重定向/错误体处理。Android 播放逻辑使用原生 ExoPlayer，不使用上游网页播放器，网页播放器模拟结果不作为 Android 播放验收。

另加入三项 Android 播放服务设备测试，用本地 WAV 检查后台切歌、通知停止与出错清理，不使用真实网易云账号或模型 API。

当前为独立功能分支的测试实现；Android 自动化结果以对应提交的 GitHub Actions 为准，真实账号扫码与手机播放还需在自己的服务上验收。当前环境的未登录搜歌探测返回 QQ 业务码 2001，并要求登录或安全验证。服务现在先检查设备自己的 QQ 登录态，未登录不会向上游搜歌；已登录遇到 2001 时提示安全验证，普通频率限制单独处理。成功搜索仅在本设备缓存 30 秒，退出或重新登录即清除。仍未完成真实账号登录后的搜歌、播放验收，不把错误提示或自动测试通过当作实际可用证明。两个平台合并后统一部署、统一验收。GitHub Actions 同时打包 Debug APK 和配套服务 ZIP。先将服务部署好，再使用 Debug 包测试，验收后安排正式版发布。
