# 西瓜瓣 · 一起听歌服务

这是供西瓜瓣 Android 客户端连接的多用户音乐服务，复用 [one-earbud](https://github.com/isle0306ral-hub/one-earbud) 的网易云协议、歌词、队列和 AI 工具实现。来源提交和 MIT 许可证保留在 `vendor/one-earbud/`；多用户适配代码位于 `src/`。

## 用户体验

1. 在西瓜瓣的设置或聊天「＋ → 一起听歌」中，连接维护者提供的 HTTPS 音乐服务地址。
2. 生成二维码，用自己的网易云扫码确认。同一台手机可先保存二维码，再在网易云扫一扫中选择文件。
3. 搜歌或浏览自己的歌单、每日推荐、私人雷达。支持播放、暂停、拖进度、切歌、顺序/随机/单曲循环、排队、调整顺序和移除歌曲。
4. 打开「和当前角色一起听」，允许该角色读取当前歌曲与附近歌词、搜索、读歌词、分享歌卡和排歌。音频在手机播放器播放，AI 收到的是文字状态。
5. 用户分享的歌曲先进入输入框草稿，可附一句话再发送。AI 分享的歌卡随工具结果保存并独立显示；翻历史记录不自动播放旧卡。

这不是把大家登录到同一个网易云账号。每个安装实例自动获得独立随机凭据，扫码、网易云登录态、队列、幂等结果和实时播放状态都按该凭据隔离。换设备或卸载后需要重新扫码，不自动合并两台设备的队列。

## 部署

要求 Docker Compose，或 Node.js 18 以上。公开服务必须通过 HTTPS 反向代理；不要直接公开容器的明文端口。

```bash
cd services/shared-music
docker compose up -d --build
```

Compose 默认只把端口映射到本机 `127.0.0.1:8787`。在现有 HTTPS 反向代理中转发到这个地址；例如 Caddy：

```caddy
music.example.com {
    reverse_proxy 127.0.0.1:8787
}
```

把实际 HTTPS 地址填写到客户端的「音乐服务地址」。域名、证书和服务器尚需由维护者配置，本仓库没有提供公共运行服务。

不用 Docker 时：

```bash
npm ci --ignore-scripts
npm test
DATA_DIR=/path/to/private/music-data PORT=8787 npm start
```

`DATA_DIR` 必须是服务专用目录。`MAX_USERS` 默认为 1000 个安装凭据；匿名新建凭据每 IP 每小时限 6 次，音乐请求每 IP 每分钟限 600 次。`MAX_ACTIVE_USERS` 默认允许同时缓存 100 个活跃安装；资源足够时可由维护者提高。最近三分钟内活跃的账号不会因缓存挤压丢失待扫二维码，达到容量时返回繁忙。每个凭据同时最多排队 20 个操作，避免重复操作无限积压。反向代理只有在服务端口无法绕过代理访问时才启用 `TRUST_PROXY=1`；Compose 已绑定本机端口。

## 账号与状态

- 随机凭据只返回给创建它的客户端一次；服务器使用其 SHA-256 作为目录名，不保存凭据原文。请求不接受客户端传入的用户 ID 或数据路径。
- 网易云登录态保存在各自目录内的 `netease-auth.json`，文件权限 `0600`、用户目录 `0700`。登录态不会通过接口返回给客户端或模型；服务管理员仍需保护整个数据卷及其备份。
- Android 用 Keystore 加密自己的连接凭据，保存在不参与备份的目录中。客户端不保存网易云 Cookie，不向模型提供服务凭据。
- 实时播放状态只在服务内存中，心跳过期后移除；客户端仅在播放/近期暂停时为已开启的角色提供一小段实时背景。不会每秒调用模型，也不把自动音乐背景写进聊天历史或记忆。
- 「退出登录」清除该凭据的网易云登录态、待扫二维码、队列和实时状态。「断开此音乐服务」还撤销设备凭据。服务离线时可以清除本机连接，但客户端会明确提示无法确认清除远端登录。
- 使用网易云非官方接口，歌曲可播范围取决于账号权限、版权和接口可用性；没有绕过会员或版权限制。

## 验证与当前范围

```bash
npm test
```

包含上游 26 项服务测试与新增 8 项多用户隔离测试。Android 测试覆盖状态过期、角色隔离、请求副本、歌曲草稿和 HTTPS/重定向/错误体处理。Android 播放逻辑使用原生 ExoPlayer，不使用上游网页播放器，网页播放器模拟结果不作为 Android 播放验收。

当前为独立功能分支的测试实现；尚未部署到公共服务器，也未完成真实账号扫码与手机播放验收。先将服务部署好，再使用 Debug 包测试，验收后安排正式版发布。
